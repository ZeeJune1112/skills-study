# Domain Docs

Before exploring the codebase, read the root `GLOSSARY.md` and any decisions in `docs/adr/` that apply to your work. If either is absent, continue silently. The `domain-modeling` skill creates these files as terms and decisions are resolved.

Use the glossary's terms in issue titles, refactor proposals, hypotheses, and tests. If a term is missing, reconsider the wording or record the gap for `domain-modeling`.

When a proposal conflicts with an existing ADR, name the ADR and explain why the decision is worth revisiting.
