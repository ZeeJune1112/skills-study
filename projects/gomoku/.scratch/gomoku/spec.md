# Windows 五子棋

Status: ready-for-agent

Implementation: authorized

用户确认工单后明确要求开始执行本规格。

## Problem Statement

玩家希望把一个文件发给同一局域网内的朋友，两台 Windows 设备双击就能对弈。朋友也能先入房观战、发送弹幕或选择空席参赛。没有对手时，玩家可以开人机房并选择难度。网络短暂中断时，玩家希望按开房时约定的规则结束或继续原来的对局。

## Solution

交付面向 Windows 11 x64 的自包含 `Gomoku.exe`、完整项目源码和打包说明。应用在局域网大厅自动显示房间。玩家可以开双人房或人机房，加入者默认进入观众席，也可在双人房选择空闲的对战席。棋盘提供落子提示、胜负显示、悔棋、重开和退出。房主在创建房间时设置观众席数量及断线处置，选择人机模式时同时设置难度。

## User Stories

1. 作为 Windows 11 x64 玩家，我希望双击单个 `.exe` 即可启动，以便直接开始玩。
2. 作为邀请朋友的玩家，我希望两台设备使用同一个程序，以便分享一个文件就能开始联机。
3. 作为房主，我希望创建双人房并获得房间标识，以便朋友能辨认我要开的房间。
4. 作为同一局域网的访客，我希望在大厅看到可加入的房间，以便从列表选择房间。
5. 作为访客，我希望进入房间后默认坐观众席，以便先看棋再决定是否参赛。
6. 作为房主，我希望创建双人房后默认坐黑席，以便客人上席后就能开局。
7. 作为想参赛的观众，我希望在开局前选择空黑席或空白席，以便加入对战。
8. 作为房主，我希望两席坐满后由我开始双人对局，以便双方准备好再下棋。
9. 作为房主，我希望创建房间时设置观众席数量，默认 5 个，以便决定能接待多少观众。
10. 作为访客，我希望观众席满时收到明确提示，以便知道什么时候可以再尝试加入。
11. 作为迟到的观众，我希望进房后看到当前棋盘、棋手和轮次，以便接着观战。
12. 作为观众，我希望实时看到后续落子、悔棋、重开和结果，以便跟上两位棋手的对局。
13. 作为观众，我希望发送滚过画面上方的弹幕，以便与房内的人分享即时反应。
14. 作为房间成员，我希望看到房内观众发送的弹幕，以便参与共同观战。
15. 作为正在下棋的玩家，我希望弹幕只做画面展示，以便点击棋盘、操作按钮和使用键盘时焦点保持在原处。
16. 作为新入房的观众，我希望只接收此后发出的弹幕，以便直接看到当前对局。
17. 作为棋手，我希望棋盘有清晰的 15×15 个交点并提示当前能落的位置，以便准确落子。
18. 作为棋手，我希望看清自己的棋色和当前轮次，以便知道何时操作。
19. 作为棋手，我希望黑棋先行、双方依次在空交点落子，以便可靠地按同一套规则对弈。
20. 作为棋手，我希望任何方向连成五枚或更多都判胜、满盘未分胜负时判和，以便清楚看到终局结果。
21. 作为双人房的棋手，我希望发起悔棋后由对手确认，以便双方同意才撤回落子。
22. 作为请求悔棋的棋手，我希望撤回到自己最近一次落子之前，以便从原来的轮次重新考虑。
23. 作为双人房的棋手，我希望重开由对手确认，以便双方都同意再清空棋盘。
24. 作为结束对局的棋手，我希望在原房间快速开下一局，以便继续对弈。
25. 作为单人玩家，我希望创建人机房后立即执黑对弈，以便无需等待其他棋手。
26. 作为人机房房主，我希望开房时选择简单、普通或困难，以便选择合适的挑战。
27. 作为人机房棋手，我希望开局后维持该局难度，以便与同一水平的对手下完整局。
28. 作为人机房房主，我希望在两局之间调整难度，以便下一局尝试不同挑战。
29. 作为人机房棋手，我希望直接悔棋或重开，以便快速练习下一种走法。
30. 作为同一局域网的访客，我希望在人机房观战并发送弹幕，以便观看朋友与电脑的对局。
31. 作为房主，我希望在开房时选择断线即中止或暂时等待，以便提前约定断线规则。
32. 作为选择等待的房主，我希望设置 15–180 秒的等待期，默认 30 秒，以便适应网络情况。
33. 作为断线或暂离的访客棋手，我希望在等待期内回到原席位、棋盘和轮次，以便接着下。
34. 作为仍在线的棋手，我希望知道对手已离线和还需等待多久，以便决定继续等还是退出。
35. 作为在线的一方，我希望立即中止或等待超时后看到中止原因，以便知道本局已结束。
36. 作为暂离的访客棋手，我希望退出房间或关闭程序后能在等待期内返回，以便继续本局。
37. 作为房间成员，我希望房主关闭程序时能看到房间结束，以便返回大厅。
38. 作为项目维护者，我希望拿到完整项目结构、核心代码和可复现的打包说明，以便修改后自行生成单文件程序。

## Implementation Decisions

- 使用 Windows 桌面应用交付大厅和对局界面。采用 WinForms 和 .NET 10，自包含、单文件发布，目标为 Windows 11 x64。开发环境使用 .NET SDK，玩家只需发布后的 `Gomoku.exe`。
- 区分房间与对局。房间承载房主、两个对战席和观众席。同一房间可开多局。双人房由房主开局，人机房创建即开局，房主执黑、电脑执白。两种房间均出现在局域网大厅。
- 将局域网发现与房内通信分开。拟通过 UDP 发现房间，通过 TCP 传递房间操作和状态。以房主程序作为当前房间的权威状态来源。加入、上席、落子、悔棋、重开和恢复连接均由房主校验。把会话消息与连接方式解耦，为后续异地对战保留传输接口。
- 局域网访客先入观众席，再选择空闲对战席。观众席默认 5 个，创建时可调整。观众席满时暂缓新访客入场，等待期内重连的参赛者可直接回原席。后加入的观众先拿到当前房间和棋盘状态，再接收后续变化。
- 自由五子棋使用 15×15 个交点。黑棋先行，仅当前棋手能在空交点落子。横、竖或任一斜向五连及长连均判胜，双方无禁手。落满且无人获胜判和棋。终局显示胜负或和棋，中止另行显示原因。
- 双人悔棋和重开由一方发起、对手确认。拒绝请求后保留棋盘。悔棋回到发起方最近一次落子之前，按棋局撤一手或两手，恢复发起方轮次。只有进行中的棋局允许悔棋。人机悔棋和重开由玩家直接执行。
- 人机难度创建时设定，对局期间固定，在两局之间可调整。简单偏随机且始终合法，普通能识别一步成五或挡五，困难增加对后续攻防的搜索。电脑计算期间界面保持可操作。
- 仅观众席可发弹幕，房内所有成员可见。弹幕从对局画面上方滚过，只展示本次消息，渲染层保持鼠标和键盘操作落在原控件上。
- 交付内容包括可双击启动的 `.exe`、完整项目结构和源码，以及构建、发布和局域网使用说明。

### 离线与续局

| 角色 | 操作 | 等待重连 | 立即中止 |
| --- | --- | --- | --- |
| 访客棋手 | 断网，窗口仍打开 | 暂停对局。网络恢复后自动回原席 | 检测到连接断开后中止本局 |
| 访客棋手 | 点「退出房间」或关闭窗口 | 暂停对局。在原设备用同一 Windows 账户重新加入该房间，恢复原席 | 中止本局，重新加入时进入观众席 |
| 观众 | 断网、退出房间或关闭窗口 | 对局继续。重新加入后同步棋盘 | 对局继续。重新加入后同步棋盘 |
| 房主 | 断网，程序仍运行 | 按访客棋手的连接状态处理，网络恢复后可限时重连 | 检测到参赛访客断线后中止本局 |
| 房主 | 点「退出房间」或关闭窗口 | 解散房间，通知在线成员返回大厅 | 解散房间，通知在线成员返回大厅 |

等待期间保留原棋盘和轮次。房主计算 15–180 秒的等待期，默认 30 秒。等待超时或双方棋手均离开时中止本局。中止不记胜负。

## Testing Decisions

- **提议的自动化入口**　通过房间会话提交动作并核对公开状态，将棋局、房间、AI 和断线策略放在同一个行为入口验收。验证观察者能看到的结果，例如落子是否合法、当前轮次、席位和终局。计时行为使用可控时钟覆盖边界。
- 会话验收覆盖 15×15 边界、错误轮次、占用交点、四种连线方向、长连、和棋、单双手悔棋、拒绝请求、确认重开、观众权限、席满、观众中途入房和对局状态同步。
- AI 验收使用可复现局面。三档均需返回合法落子，普通档覆盖一步获胜和一步阻挡，困难档另验证当前一步之外的攻防。覆盖开局锁定难度和局间调整。
- 离线验收覆盖立即中止、默认 30 秒、15 秒和 180 秒边界、访客断线或退出后恢复原棋盘和轮次、等待超时、观众重新加入、房主程序关闭，以及两名棋手均离开。已预留的对战席应可在观众席满时恢复。
- **提议的发布验收**　把单个 `.exe` 拷到没有额外安装 .NET 的 Windows 11 x64 环境双击启动。在两台同局域网设备上验证自动发现、加入、轮流落子和断线恢复。增加第三个客户端验证观战同步、弹幕滚动与操作焦点。发布验收以实际设备和环境结果为准。
- 会话层检查由 `tests/Gomoku.Checks` 执行。同机发布版回归由 `tests/Windows/smoke.ps1` 执行，覆盖退出与续局、观众重进、房主关窗、人机启动和实际最小窗口。

## Out of Scope

- 异地对战的公网发现、匹配、穿透、中继和云端服务。
- Windows 10 和 Windows ARM64 发行包。
